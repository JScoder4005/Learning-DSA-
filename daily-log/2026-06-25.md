## What I Learned
- The "complement" trick in Two Sum changes the question completely — instead of "find two numbers", ask "have I seen the number I need?" This mental flip is reusable everywhere.
- Kadane's algorithm is the simplest Dynamic Programming pattern — you only ever need the previous state, not the whole history.
- Linked list problems can't be reasoned about without drawing arrows on paper.
- Memoization is just "cache the result, return it if asked again" — that's it.

## Blockers / What Was Confusing
- The `[prev, curr] = [curr, prev + curr]` destructuring in Fibonacci: easy to forget it evaluates the right side first before assigning.
- `stack.pop()` returning `undefined` on empty stack — this is actually useful for the Valid Parentheses edge case `")("`.

## Approach Comparison
| Problem | Naive | Optimal | Gain |
|---------|-------|---------|------|
| Two Sum | O(n²) nested loops | O(n) hash map | 10x faster at n=1000 |
| Fibonacci | O(2^n) recursive | O(n) memoized / O(1) iterative | Exponential → linear |
| Binary Search | O(n) linear scan | O(log n) binary | 1B items: 1B checks → 30 checks |
| Flatten Array | Fixed nested loops (can't work) | O(n) recursion | Only way for unknown depth |
